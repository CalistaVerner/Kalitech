# AEGIS

AEGIS — подсистема производительности и изоляции Lua-runtime в Kalitech.

## Цели

- ограничивать объём работы в кадре;
- выполнять изменения сцены на JME-потоке;
- отделять runtime приложения от runtime миров;
- измерять очереди, системы и пользовательские метки;
- сохранять детерминированный порядок систем.

## Планировщик

Каждая система получает фазу, порядок и бюджет. Worker-задачи не изменяют сцену напрямую: результат передаётся в очередь главного потока.

```lua
ctx:perf():mark("shoot:spawn")
ctx:perf():main():enqueue(function()
    spawnBullet()
end)
```

При перегрузке очередь применяет backpressure, а profiler фиксирует размер очереди, задержку и превышения бюджета.

## Runtime

Lua-runtime привязан к одному потоку. Модули кешируются по каноническому id, зависимости отслеживаются автоматически. Hot reload инвалидирует изменившийся модуль и его потребителей.

Публичные значения пересекают Java/Lua-границу через `LuaValueRef`, `LuaObject` и `LuaArray`. Доступ к host-методам разрешается только через экспортированный API.

## Диагностика

`FrameStats`, `PerfMarks` и profiler-модуль позволяют строить HUD без обращения к внутренним объектам движка. Для анализа доступны:

- frame time и tick time;
- время отдельных систем;
- длина очередей;
- число событий;
- пользовательские marks;
- длительные операции и исключения.

AEGIS не меняет публичный Lua-контракт модулей: игровая логика использует `ENGINE.<module>`.
